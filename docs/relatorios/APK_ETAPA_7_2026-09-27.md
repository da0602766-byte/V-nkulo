Não há promessa de build bit a bit idêntico nem de auditoria integral das bibliotecas. Checksums fixam o conteúdo aprovado; o bootstrap inicial parte dos repositórios configurados. O build de referência validado é Linux/CI. Nenhuma mudança nas APIs do servidor, protocolos ou schema local é necessária para esta versão.

## Atualização e recuperação

O workflow mantém a cadeia de releases com a assinatura de produção, incluindo a 1.13.0. A etapa adicional compila a fonte anterior `f4cacf1ef16eda70eec59b4d574456435e3f5106` em debug e instala um runner de teste separado no emulador descartável.

Na 1.13.0, cria sete registros: visitante nos estados DRAFT/PENDING/RETRY/SENDING/CONFLICT/CONFIRMED e uma nota pendente. Encerra o processo e atualiza para 1.14.0 com `adb install -r`. Verifica `firstInstallTime`, identidade do aparelho lógico, UUID, estados, os mesmos bytes cifrados, isolamento entre contas e leitura usando a chave original. Em uma cópia de teste, recupera um lease expirado com o mesmo UUID e recusa confirmação atrasada do worker anterior. Repete a verificação em outro processo.

Esse ensaio usa assinatura debug igual entre os dois builds, separadamente do ensaio de releases assinados. Fixtures/runner de teste não integram o APK release. Nenhum dado sintético é escrito em produção. Os testes de migração Room e filas das etapas anteriores permanecem na suíte.
